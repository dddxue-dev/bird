### 漏洞链路（已实测）
注册 `birdadmin'#` → 原样落库 → 登录（登录处已转义，不可注入）→ 改密页
`UPDATE users SET password='x' where username='birdadmin'#' and password='...'`
`#` 注释掉后半段 → birdadmin 密码被改写 → 登录 birdadmin → 拿 Flag。
**注意：`#` 连"当前密码校验"一起注释掉了，当前密码填错也能成功。**

### 追加：反捷径审计（断言从 19 → 30 项）
新增 `[6] 防意外捷径审计`，全部通过。关键发现：
- Flag 判断是 PHP 严格比较 `$_SESSION['username'] === 'birdadmin'`，
  所以**即使能注册出变体也拿不到 Flag**，防线是双层的。
- MySQL `utf8mb4_general_ci` 排序规则下：`BirdAdmin` / `BIRDADMIN` / `birdadmin `（尾随空格）
  会被 UNIQUE 索引判为重复 → 注册被拦；
  而 ` birdadmin`（前导空格）/ `birdadmin\t` **能注册成功**，但 `=== 'birdadmin'` 不成立，无 Flag。
- 登录密码字段注入、注册接口注入、单独伪造 `Auth` cookie 全部无效。
- 结论：唯一可行路径就是二次注入。

已把「防意外捷径审计」写进 skill `php-ctf-web-challenge` 的第七节（排序规则陷阱 + 双层防线）。

### 踩坑（值得记住）
- **`.stat` 是为深色区设计的**：数字用 `--clay-lite`、标签用浅色 rgba，
  搬到浅色区块后几乎看不见。已加 `.stats.on-light` 修饰类覆盖，不改基础类。
  → 这个问题 `php -l` / `node --check` / HTTP 200 全都查不出来，**只有真截图才能发现**。
- **headless Chrome 截图必须加 `--no-proxy-server`**：环境里 `http_proxy`/`https_proxy`
  指向本地代理，Chrome 访问 127.0.0.1 走代理 → 截出来整张全白（Chromium 错误页）。
  `curl` 同理要 `--noproxy '*'`。
- **静态服务要用后台常驻**：`( python -m http.server & )` 会在命令结束时被回收。
- **滚动出现动画会让截图出现空白/幽灵文字**，加 `--force-prefers-reduced-motion` 截稳定终态。
- **交互测试免 playwright 的招**：同源 iframe + `contentDocument` 真实点击，
  结果写进 `document.title`，再 `chrome --dump-dom | grep '<title>'` 读。
  实测一次验证 4 个筛选按钮：12 → 5/4/3 → 12，激活态同步，全部正确。
